# 猛玛 LARK A2 无线麦克风电适配说明

日期：2026-11-09。来源：**官方 WebHID 网页**（不是猜的，也不是抓包猜出来的）。

## 为什么是网页

猛玛给 LARK A2 的电脑端工具是一个网页：[res.hollyland.com/6118](https://res.hollyland.com/6118/index.html)。它用 `navigator.hid.requestDevice()` 直连接收器，所以协议全部以明文 JS 的形式躺在那 8.6 MB 的页面里。

## 设备与通道

| 项 | 值 |
| --- | --- |
| VID:PID | `3547:0411`（Shenzhen Hollyland Technology） |
| 产品名 | `Wireless Microphone` |
| 使用通道 | Usage Page `0xFF90` / Usage 1，in 64 / out 64 |
| report id | `0x55`（收发同号） |
| 另一通道 | `0xFF82` / report id `0x41`（本适配未使用） |

## 帧格式

```
请求（63 字节，不含 report id）
  [0] 0xAA  [1] 0xDD  [2] cmd  [3] device
  [4..5] payload 长度（大端）
  [6..]  payload

响应（读到的原始 report 含前置 report id 0x55）
  [1] 0xBB  [2] 0xDD  [3] cmd  [4] device
  [5..6] 长度（大端）
  [7..]  payload
```

设备字节：接收器 `0x40`、TX1 `0x41`、TX2 `0x42`；响应里 `0x81` = TX1、`0x82` = TX2。

## 命令

命令字节的真值来自手机 APP v3.2.2 的 `Command6118Usb` 枚举（反编译，取证过程见文末）；网页侧只覆盖其中一部分。

| 名称 | 值 | 用途 | 本项目 |
| --- | --- | --- | --- |
| `DEVICE_VERSION_GET` | `0x03` | 设备版本 | — |
| `HEART_GET` | `0x10` | 心跳：在线、电量、降噪档、音量、声道、灯、美声、静音/充电 | ✅ 读 |
| `VOICE_LEVEL_GET` / `SET` | `0x04` / `0x05` | 接收器音量 0–5 | 只发 `0x05`；音量读自心跳第 7 字节 |
| `NOISE_LEVEL_SET` | `0x06` | 降噪档位 0–3 | ✅ 写 |
| `DEVICE_ID_GET` | `0x08` | 设备 ID | — |
| `NOISE_LEVEL_GET` | `0x11` | 降噪档位 | — |
| `SPEAKER_SET` / `GET` | `0x12` / `0x13` | 监听开关 | — |
| `DEVICE_SN_GET` | `0x15` | 序列号 | — |
| `VOICE_MODE_SET` | `0x18` | 声道模式 0 / 1 / 2 | ✅ 写 |
| `NOISE_SWITCH_SET` | `0x19` | 降噪开关（切换） | ✅ 写 |
| `VOICE_LOCK_SET` / `GET` | `0x34` / `0x35` | 按键锁定 | — |
| `SHUTDOWN_TIME_SET` | `0x36` | 自动关机时间 | — |

| `BEAUTY_VOICE_SET` | `0x3A` | 美声/EQ `[enable, preset]` | 仅读心跳 |
| `TX_IDENTIFY_SET` / `GET` | `0x3B` / `0x3C` | 查找发射器 | — |
| `SMART_BATTERY_SET` / `GET` | `0x3D` / `0x3E` | 智能续航 | — |

| `RESTART_RX` | `0x0C` | 重启接收器（会掉线） | — |
| `OTA_*` | `0x09` / `0x0B` / `0x0D` / `0x0E` | 升级链路（TX 升级、结果、RX 升级、包确认），**不要碰** | — |

`cmd | 0x80` 对**读命令**是等价的别名：`0x83`/`0x84`/`0x90`/`0x91`/`0x93`/`0xBC`/`0xBE` 的回包与 `0x03`/`0x04`/`0x10`/`0x11`/`0x13`/`0x3C`/`0x3E` 逐字节相同（2026-11-09 实测）。

⚠️ 但**不能推广到写命令**：`0x85`/`0x86`/`0x88`/`0x89` 的回包（`01`、`0100`、`00`、`00`）与它们对应的写命令语义不符，跟着的结论见下面「未登记命令」一节。

## HEART payload 字段（完整）

字段顺序来自手机 APP 的 `CmdGetHeart6118`，与本机实测逐字节一致（例如 `01 00 5a 00 00 00 00 00 00 00 00 00 00 00 04 00`）。

| 索引 | 含义 | 状态 |
| --- | --- | --- |
| 0 | TX1 在线（1 = 在线） | ✅ 实测 |
| 1 | TX2 在线 | ✅ 实测 |
| 2 | TX1 电量百分比 | ✅ 实测 |
| 3 | TX2 电量百分比 | ✅ 实测 |
| 6 | 降噪档位 0–3（0 = 关闭；APP 里 `noiseOpen = noiseLevel != 0`） | ✅ 实测 |
| 7 | 接收器音量 0–5 | ✅ 实测 |
| 9 | 声道模式 0 = 单声道 / 1 = 立体声 / 2 = 安全音轨 | ✅ 实测 |
| 10 | 自动关机（APP 按 `== 0` 判「开启」，语义反常，本适配不采用这个判断） | 未验证 |
| 13 | 指示灯（`== 0` 视为开；写 `0x39[1]` 关灯） | ✅ 实测 |
| 14 | bit0 = 美声开关，bit1–7 = 美声预设号（关闭时仍保留上次的预设号，别当「当前选择」显示） | ✅ 实测 |
| 15 | bit0/1 TX1/TX2 静音，bit2/3 TX1/TX2 充电（✅ 实测）；bit4 相机接收器充电（**推断**，本机这一位恒 0） | 部分实测 |
| 16 | 相机接收器电量（**推断**）：APP 会读这一字节，本机回包只有 16 字节、索引 16 不存在，代码按未知处理 | 未观测 |

## 本适配的取舍

- 双发射器取**在线发射器的最低电量**；两个都离线时返回未知，不显示 0%。
- 充电位按位判断，但实机当时未充电，**该位未实测验证**。
- 写入只开放**实机闭环验证过**的那些：降噪档位/开关、声道模式、接收器音量、指示灯。模板、语言、配对、恢复出厂、OTA 一概不碰。
- 电量小于等于 100 才接受，超出按无效处理。

## 控制功能（2026-11-09 追加验证）

网页驱动只覆盖设备的一部分命令。本适配先做完**电量 + 降噪**，再从手机 APP 补上声道模式、接收器音量与指示灯（取证见文末）。

### 降噪的真实机制

- 降噪档位**不是**用 `NOISE_LEVEL_GET` 单独查询，而是心跳 `HEART_GET` 的 **payload 第 6 字节**（0 = 关闭，1/2/3 = 10/15/20 dB）。
- `NOISE_SWITCH_SET (0x19)` 是**切换**（toggle），不是设值；payload 固定 `[0x02]`，每发一次状态翻转。
- `NOISE_LEVEL_SET (0x06)` 才是设档位，payload `[level]`。
- 网页的开启流程是「先发 0x19 打开，再发 0x06 设档位」。

### 实机闭环（2026-11-09 22:2x）

```
心跳 noise=0 → 0x19 → 心跳 noise=1 → 0x06[2] → 心跳 noise=2 → 0x19 → 心跳 noise=0
```

四个状态全部读回一致，证明开关与档位都是真的在改设备。

### 已实现

`app/lark_a2_control.py`：

- `build(cmd, payload, device)` — 6118 帧构建（64 字节含 report id）
- `parse_heart(payload)` — 在线/电量/降噪档/静音/充电，以及音量、声道、灯、美声
- `parse_set_ack(raw, cmd)` — 写命令回执（成功 = `01`）；只接受写命令，长度必须正好 1 字节，其它命令抛错
- `noise_level_request(level)` — 0–3，越界抛错
- `noise_switch_request()` — 切换开关
- `voice_mode_request(mode)` — 声道模式 0/1/2
- `voice_level_request(level)` — 接收器音量 0–5
- `light_request(on)` — 指示灯，线序取反（0 = 开）
- `channel_mode_name(mode)` — 声道中文名，未登记的值返回 `None`

未实现：模板（0x42/0x43）、模板信息（0x44/0x45）、按键名（0x46/0x47）、语言（0x4E）。这些协议已知但需模板 CRUD 与校验，未做。

### 未登记命令的扫描结果（2026-11-09 22:5x）

用户指出手机 APP 也是插接收器走 2.4G，因此单双声道等功能**应该**在同一个 HID 通道里，只是官方网页没实现。据此扫了 `0x80–0xFF`，发现网页命令表之外的读命令：

| 命令 | 回复 (RX) | 观察 |
| --- | --- | --- |
| `0x83` | `0300021a` | 结构类似 `RULE_VERSION_GET`，疑似另一组版本号 |
| `0x84` | `05` / `00` | **值会变**（同一台设备两次读到不同值），最像某个可切换的工作状态 |
| `0x85` | `01` | 恒定 |
| `0x86` | `0100` | 两字节，疑似一个布尔对 |
| `0x88` / `0x89` | `00` / `00` | 恒定 |

⚠️ **危险区**：从 `0x8D` 开始连续多个命令会让接收器直接掉线（`WriteFile err=1167`，随后设备重新枚举）。扫描时必须从 `0x8D` 处截断，不要整段扫。

其中 `0x83` / `0x84` **已查明**是 `0x03` / `0x04` 加 `0x80` 读位（回包逐字节相同，`0x84` 就是「读接收器音量」，所以两次扫描读到不同值）；同批的 `0x90` / `0x91` / `0x93` / `0xBC` / `0xBE` 也已实测等价。

⚠️ `0x85` / `0x86` / `0x88` / `0x89` **仍然未知**：`0x85` / `0x86` 对应的是写命令 `0x05` / `0x06`，「读别名」解释不了它们恒定的回包，弄清前不要当读命令用。

### 关于手机 APP 的独有功能（旧结论已推翻）

旧结论写的是「单双声道属于蓝牙/私有协议，电脑端 WebHID 没有这条通路」——**这条是错的，已删除**。

网页 JS 里 `channel` / `stereo` / `mono` / `声道` / `立体声` 确实零命中，但那只说明**网页没实现**，不等于设备不支持。手机 APP 插的是同一个 2.4G 接收器，走的还是这条 `0xFF90` HID 通道；反编译 APP 后直接发同名命令，实机全部成功（下一节）。

## 手机 APP 取证（2026-11-09 23:1x）

APK：`猛玛音频 v3.2.2`（`com.hollyland.larkc1`，8 个 DEX）。用 jadx 1.5.6 反编译 `classes5.dex`（设备页/UI）与 `classes6.dex`（协议层）后定位到：

| 位置 | 作用 |
| --- | --- |
| `...protocol.core.sound.command.type.Command6118Usb` | 命令字节真值，即本文命令表的来源 |
| `...command.device6118.LegacyUsb6118ProtocolCodec` | 帧编解码：`AA DD`/`BB DD`、设备 0x40/41/42、大端长度 |
| `...command.device6118.CmdGetHeart6118` | 心跳字段布局（APP 侧带设备前缀算 17 字节，线上 payload 是 16 字节） |
| `...command.device6118.CmdSetVoiceMode6118` | 声道模式写命令，payload 一个字节 |
| `...ui.home.C6118DeviceActivity#setupVoiceModeActions` | 三个按钮的取值：单声道 0 / 立体声 1 / 安全音轨 2 |

⚠️ 一个容易踩的坑：APP 的 `payloadBody()` 会丢掉 payload 第一个字节，因为框架把「逻辑设备号 0/1/2」先塞进 payload、编码时再提帧头。**线上报文没有这个前缀**，所以照 `payload[0] = TX1 在线` 解析才对（本机实测一致，别照抄 APP 的下标 +1）。

### 实机闭环（2026-11-09 23:1x，每次写完都重读心跳）

```
声道   0 → 0x18[1] → 1 → 0x18[2] → 2 → 0x18[0] → 0
音量   0 → 0x05[1] → 1 → 0x05[0] → 0   （0x05[8]/[16]/[100]/[255] 一律读回 5，故上限 5）
指示灯 0（开）→ 0x39[1] → 1（关）→ 0x39[0] → 0（开）
美声   [0,0] → p14=0x04；[1,0] → 0x01；[1,2] → 0x05（关闭时不改预设号）
```

写命令回执长这样：`55 bb dd 18 80 00 01 01`（cmd 原样回、device `0x80`、长度 1、值 1 = 成功），`parse_set_ack` 就是解它。

⚠️ **没有实机验证**的写命令，一概不算已适配：监听 `0x12`、按键锁定 `0x34`、自动关机 `0x36`、查找 TX `0x3B`、智能续航 `0x3D`、解除配对 `0x3F`、恢复出厂 `0x40`。

另有一条**试过但故意不开放**的：美声 `0x3A` 在上面闭环里写过三次（`[0,0]` / `[1,0]` / `[1,2]`），设备每次都回 `01`、心跳 p14 也如实变化；但本适配只**读**美声状态，不给写入口 —— 预设号的实际听感含义没验证过，不该让工具去改。
